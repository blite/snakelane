    snakelane¶

    An opinionated App Store Connect CLI for indie Apple developers and coding agents. Keep listings, screenshots, and purchase catalogues in your repo, review changes, and ship with a focused Python workflow.

    snakelane store push sends listing text, categories, screenshots, App Previews, in-app purchases and subscriptions to the App Store Connect API from plain-text files. snakelane ship runs test → archive → TestFlight → review. An Archive post-action keeps build numbers right.

    It covers the parts of fastlane a small app uses, without Ruby, lanes or a Fastfile. It is written in Python, so a failure in CI is a readable traceback in a file you can open. It comes with an agent skill, so a coding agent can run it, and fix it when it's wrong.

    Once per machine, install an App Store Connect API key with snakelane auth setup. Then:

    snakelane lint                     # what App Review would reject
snakelane store push --dry-run     # everything that would change, offline
snakelane store push               # diff against live, confirm, write, verify
snakelane shoot                    # the screenshot deck, from your UI test
snakelane gallery --live --open    # every deck beside what's live
snakelane store screenshots push
snakelane ship beta                # test → archive → TestFlight

    Framed for the App Store¶

    snakelane frame captions your screenshots in three layouts (the caption over the screenshot, above it, or above it shown as a card), in eight built-in looks or your own. Every one is on the Screenshot showcase; Framing screenshots explains the settings.

    This repo shouldn't exist

    Keeping your store listing, screenshots and purchases in your repo, and shipping them alongside the build, should be core functionality in Xcode. Apple has shown it can do this: Game Center configuration lives in a .gamekit file in your project and syncs both ways with App Store Connect. Until the rest of the listing works like that, there's snakelane.

    What it does¶

    Listing

    • Push, pull and show listing text, categories, copyright and App Review details from plain text files, with per-locale overrides over a shared default/
    • A word-level diff of every change before you confirm, then a re-read that verifies it landed
    • Never pushes a blank: a missing or empty file leaves the live field alone
    • Pre-review lint (lint): over-limit fields, other platforms named, placeholders, beta and "coming soon" wording, keyword waste, dead URLs; gates store push and ship release
    • Translation tracking (translations): which translated fields are stale or unreviewed
    • Age rating questionnaire and categories from the config, categories checked against Apple's list before anything is written
    • Release notes drafted from the commits since the last release, for the agent to rewrite and you to edit
    • Pre-review checks for release notes left unchanged since the last version, and for locales with screenshots but no translated text

    Screenshots and previews

    • Shoot the deck from your own UI test across devices and locales, on simulators or the Mac
    • A failed shoot leaves the previous deck exactly as it was
    • Redraw caption banners without re-shooting (frame)
    • Caption styles from three separate settings (layout, caption shape and theme), with 8 built-in themes and a preview that leaves the deck alone (frame --theme)
    • The app leaves room for the caption: shoot hands it the band's depth
    • Push screenshots and App Previews, with the slot worked out from pixel size, the 10-per-set limit enforced, and Apple's processing waited on
    • Warnings for sizes other than the 6.5" iPhone and 13" iPad defaults
    • OCR check that refuses a deck shot from a debug build (check)
    • HTML review page (gallery): every deck against what's live or the last commit, App Store search-result and product-page mocks, lint and translation status per locale
    • Caption-only localization: translated banners over the primary language's shots, with per-locale captions and fonts

    In-app purchases

    • One-time purchases and subscription groups from one iap.yml; creation only behind --create, because product ids are permanent, and an id used twice is refused. Subscription prices are set once on App Store Connect's website, where one price covers every territory

    Downloadable content

    • Background Assets packs: content Apple hosts and your app downloads after install, instead of shipping it in the binary. Package, verify and upload with packs

    Shipping

    • ship test | beta | release: test, archive, upload, TestFlight changelog from git, attach, submit for review
    • Build numbers from an Archive post-action: max(project + 1, TestFlight + 1), stamped into the app and every extension
    • ship bump-version for the marketing version
    • Release controls: after approval, manual or scheduled, and phased release, from the config
    • status: versions, review in progress and the latest TestFlight build, in one view
    • One auth method: a team API key installed once with snakelane auth setup; no environment variables, no Apple ID sign-in
    • Upload dSYMs to Sentry after a ship
    • Slack notification when a ship finishes or fails
    • Code signing for CI runners (under discussion: Xcode's automatic signing covers a Mac today)

    Setup and scripting

    • init reads the Xcode project (scheme, bundle id, team, platforms) and writes the config and starter listing files
    • --json on status, store show, lint and translations status

    Agents

    • An agent skill that knows how to drive snakelane, its App Store Connect traps, and how to fix snakelane itself

    Where to start¶

    • New to snakelane: read Getting started, then The config and the metadata tree.
    • To try it before setting up an app, run it against the repo's examples/: one app, and two apps sharing a repo. Neither needs an API key.
    • To caption your screenshots: Framing screenshots explains the settings, and the Screenshot showcase shows every look.
